# Behobene Sicherheitsprobleme - ssh-easy

- **F9 „mit Standardprogramm öffnen“ abgesichert (Build 60, 2026-10-22)** – vorbeugend beim Bau: Die Datei stammt vom Server; über das Standardprogramm würde z. B. eine `.exe`, `.bat`, `.ps1`, `.lnk`, `.hta` oder unter Linux eine `.desktop`-Datei **ausgeführt**. Fix: Sperrliste ausführbarer/Skript-/Installer-/Abbild-Typen (`blockedOpenExtensions`). Der lokale Name wird vorher Windows-sicher gemacht (`localOpenName`): Steuer-/Formatzeichen und `<>:"/\|?*` → `_`, reservierte Gerätenamen (CON, NUL, COM1 …) erhalten `_` davor, Punkte/Leerzeichen am Ende werden entfernt – sonst hätte `evil.exe.` die Prüfung umgangen (Windows entfernt sie stillschweigend) bzw. `harmlos.txt:evil.exe` einen alternativen Datenstrom erzeugt. Herunterladen in eigenen Ordner je Datei (`os.MkdirTemp`, 0700; Datei `O_EXCL`, 0600), Größengrenze 1 GiB, Windows: Mark of the Web (`Zone.Identifier`, ZoneId=3) für geschützte Ansicht/SmartScreen. Öffnen ohne Shell (Windows `ShellExecute`, Linux `xdg-open` direkt) – keine Quoting-/Injektionsprobleme. Aufräumen beim Beenden, Reste beim nächsten Start. Tests `TestLocalOpenName`, `TestBlockedOpenExtension` (inkl. Tricks), `TestViewerF9*`, `TestCleanupStaleOpenDirs`. Regex-Suche im Betrachter nutzt Gos RE2 (lineare Laufzeit, kein ReDoS).

- **Datei-Manager-Kopieren gehärtet (Build 58, 2026-10-21)** – eigene Analyse auf Nutzerfrage + automatisches Security-Review von Build 57 (security-guidance-Plugin): (1) MITTEL – private Dateien waren während der Übertragung mit Server-Standardrechten (meist 0644) lesbar, neue Verzeichnisse bis zum Ende. (2) MITTEL – Symlink-Wettlauf: zwischen Lstat und Anlegen konnte ein Symlink untergeschoben werden. (3) MITTEL – zwei Verbindungseinträge (Name/IP) auf denselben Server: Anlegen der Zieldatei leerte die Quelle. Fix für 1–3: `copyData` schreibt in eine exklusiv angelegte Temp-Datei (`O_EXCL`, Präfix `.ssh-easy-copy-`), setzt sofort 0600 (lässt der Server das nicht zu und ist die Quelle privat → `errCannotProtect`, nicht kopieren), setzt nach dem Schreiben Rechte/Zeit und benennt per `posix-rename@openssh.com` in einem Schritt um (Fallback: Datei/Symlink entfernen + Rename). Symlinks ebenso über Temp-Namen. Neue Verzeichnisse sofort 0700. Tests `TestCopyPrivateFileNeverReadable`, `TestCopyPrivateFileChmodForbidden`, `TestCopySymlinkPlantedDuringCopy`, `TestCopyOntoItselfViaOtherHostName`; E2E gegen echten sshd (Symlink am Ziel auf fremde Datei → fremde Datei unverändert). (4) HOCH (Review) – Namen mit `\` (Pfadtrenner bei Windows-SFTP-Servern) und Steuerzeichen werden beim Kopieren abgelehnt (`safeCopyName`), zusätzlich prüft `insideDir` jeden Zielpfad; `:` bleibt erlaubt (unter Linux normales Zeichen, mitten im Pfad auch unter Windows kein Ausbruch). Tests `TestCopyRejectsWindowsAndControlNames`, `TestCopyInsideTargetDir`. (5) NIEDRIG – unsichtbare Formatzeichen (Bidi-Steuerung U+202A–202E/U+2066–2069, ZWSP, BOM …) in Dateinamen werden als `?` angezeigt (Joiner U+200C/U+200D bleiben, Persisch). (6) MITTEL (Review) – Absturz durch absurde Größen eines bösartigen Servers (Überlauf → negative Länge in `strings.Repeat`): `satAdd` (sättigend, ≥ 0), Fortschritt als Kommazahl, Balken auf [0, Breite] begrenzt. Test `TestCopyHugeSizesNoCrash`. (7) NIEDRIG – endlose Bäume: Erfassen bricht nach 1 000 000 Einträgen bzw. 128 Ebenen ab (`errCopyLimit`, nichts wird kopiert). Test `TestCopyScanLimits`.

- **Datei-Manager-Kopieren: Path Traversal, Schreiben durch Symlinks, Kopieren auf sich selbst (Build 57, 2026-10-21)** – vorbeugend beim Bau von F5 (eigene Prüfung vor dem Build): (1) Ein bösartiger Quellserver könnte in einer Verzeichnisliste Namen wie `../../etc/x` liefern; beim Kopieren hätte `path.Join(Zielverzeichnis, Name)` auf dem *anderen* Server außerhalb des Zielverzeichnisses geschrieben. Fix: `safeEntryName()` lehnt leere Namen, `.`, `..` und Namen mit `/` ab – beim Kopieren (Fehler `errUnsafeName`, übersetzte Meldung) und schon in der Anzeige (`readPanelDir`). Tests `TestCopyRejectsUnsafeNames`, `TestReadPanelDirSkipsUnsafeNames` (mit präpariertem Server-Fake). (2) Steht am Ziel ein Symlink, wird er beim Überschreiben entfernt statt durch ihn hindurch zu schreiben (sonst Überschreiben beliebiger Dateien, auf die der Link zeigt). Test `TestCopyOverwriteSymlinkTarget`. (3) Gleicher Server + gleicher Pfad wird abgelehnt (`errSameFile`), sonst würde das Anlegen der Zieldatei die Quelle leeren. Test `TestCopySameFileOnSameHost`. Außerdem: Dateinamen und Fehlertexte in allen Kopierdialogen laufen durch `sanitizeFileName()`.

- **Terminal-Escape-Injektion über Fehlertexte (Build 54, 2026-10-21)** – MITTEL (automatisches Security-Review von Build 53, security-guidance-Plugin): Die Datei-Manager-Meldungen für Verbindungs-, SFTP- und Host-Key-Fehler gaben `err.Error()` ungefiltert aus; SSH/SFTP-Fehler können vom Server gesendeten Text enthalten. Dasselbe Muster bestand schon länger im normalen Verbindungsaufbau (`sshErrorMsg`) sowie bei Key-Deployment/-Entfernung. Fix: alle diese Texte laufen durch `sanitizeFileName()` (Steuerzeichen und ungültiges UTF-8 → `?`). Tests `TestFileManagerConnectErrorsSanitized`, `TestConnectErrorSanitized` (scheiterten vor dem Fix).

- **Datei-Manager: Terminal-Escape-Injektion über Dateinamen verhindert (Build 53, 2026-10-21)** – vorbeugend beim Bau des Datei-Managers: Dateinamen, Pfade und Fehlermeldungen kommen vom (nicht vertrauenswürdigen) Server; ein Name mit `ESC[…`-Sequenz hätte das lokale Terminal steuern können (Bildschirm löschen, Titel setzen, bei manchen Terminals Antworten einschleusen). `sanitizeFileName()` ersetzt alle Steuerzeichen (C0, DEL, C1) und ungültiges UTF-8 durch `?`, bevor etwas angezeigt wird. Test `TestSanitizeFileName`. Weitere Eigenschaften: Datei-Manager-Verbindungen nutzen dieselbe known_hosts-Prüfung wie normale Verbindungen (geänderter Host-Key → Abbruch mit Meldung, keine Bestätigung im Datei-Manager), öffnen keine Tunnel, Passwörter werden nicht gespeichert und das Passwortfeld nach jedem Versuch geleert; Symlinks auf Verzeichnisse werden nicht verfolgt.

- **Scanner-Lauf 2026-10-17 (worker-security 2.0.0, Build 51)** – 0 kritisch, 25 hoch, 28 mittel:
  - **HOCH: Auto-Update ohne Signaturprüfung (CWE-494, Befund #25)** – Prüfsumme und Binary kamen beide von GitHub; wer das Konto bzw. den (im Klartext notierten) Token kontrollierte, konnte beides austauschen, und alle Auto-Update-Nutzer hätten es installiert (Windows: mit Adminrechten). Fix: Neues Paket `src/releasesig`: Jedes Release enthält `ssh-easy-SHA256SUMS` (Kopfzeile `ssh-easy release <Tag>` bindet die Liste an genau ein Release, kein Replay alter Listen) und `ssh-easy-SHA256SUMS.sig` (Ed25519 über Kontext-Präfix + Liste, Domain Separation). Der öffentliche Schlüssel ist in `updater.go` eingebettet, der private liegt nur unter `~/.config/ssh-easy/release-signing.key` (0600, `LoadPrivateKey` lehnt offene Rechte ab). `build.sh` signiert über `src/cmd/release-sign`. Der Updater nimmt die SHA-256 nur noch aus der signierten Liste; eine abweichende API-Angabe führt zum Abbruch, unsignierte Releases werden abgelehnt. Strenger Parser (nur `[A-Za-z0-9._-]`-Dateinamen, 64 kleine Hex-Zeichen, keine Dubletten, Größenlimit 64 KiB). Tests: `tests/releasesig_test.go` (11) und 8 neue Updater-Tests; Mutationsprobe (Signaturprüfung abgeschaltet) lässt `TestCheckAndDownloadForeignSignature` scheitern.
  - **MITTEL: Close-Fehler beim Anhängen an known_hosts ignoriert (CodeQL, Befund #147)** – `appendKnownHost` meldet jetzt den Fehler von `Close()`; ein unvollständig geschriebener Host-Key galt sonst als gespeichert.
  - **24 × HOCH „Zero-Width Characters“ → False Positive**: Es handelt sich ausschließlich um U+200C (ZWNJ) in Kannada-, Telugu- und Persisch-Übersetzungen, orthografisch notwendig. Absicherung gegen echte „Trojan Source“-Angriffe (CVE-2021-42574): `tests/source_hygiene_test.go` verbietet Bidi-Steuerzeichen, ZWSP, Wortverbinder, BOM und Soft-Hyphen in allen Go-Dateien und erlaubt ZWNJ/ZWJ nur in Texten der i18n-Dateien.
  - Übrige 27 MITTEL-Funde im Triage-Werkzeug mit Begründung als False Positive/irrelevant markiert (z.B. HMAC-SHA1 ist vom OpenSSH-Format gehashter known_hosts vorgegeben; Tunnel-Streams sind bewusst unbegrenzt; Download-`io.Copy` liest aus `LimitReader`).

- **Automatischer Security-Review von Build 48 (security-guidance-Plugin, Build 49, 2026-10-16)** – zwei MITTEL-Funde:
  - **DNS-Fallback (dns-spoofing / info-leak)**: Antworten öffentlicher DNS-Server sind unverschlüsselt und fälschbar; ein noch unbekannter Host-Key wurde trotzdem automatisch in known_hosts übernommen (Trust-on-first-use). Fix: `resolve()` meldet, ob die Adresse vom Fallback stammt; dann lehnt `getHostKeyCallback(false)` unbekannte Keys mit `untrustedHostError` ab (übersetzte Meldung in der TUI, keine Passwortabfrage). Interne Namen (ohne Punkt, `.local`, `.lan`, `.internal`, `.home.arpa`, `.fritz.box` u.a.) gehen nie an öffentliche Server. Den Fallback ganz abzuschalten oder DoH zu nutzen wurde nicht übernommen: Der Fallback ist ausdrücklich gewünscht, bekannte Hosts schützt known_hosts. Tests in `tests/host_key_fallback_test.go`, `TestIsInternalHostName`, `TestResolveInternalNameSkipsFallback`, `TestResolveReportsFallbackUsage`.
  - **Admin-Setup aus benutzerschreibbarem Ordner (privilege-escalation)**: DLL-Hijacking neben dem mit Adminrechten gestarteten Setup. Fix: eigener, frisch angelegter Unterordner pro Setup (`os.MkdirTemp`, unter Windows Owner-only-DACL), vor dem Start `checkSetupDirectoryClean()` (nur das Setup darf im Ordner liegen). NSIS 3 lädt System-DLLs zusätzlich selbst nur aus System32. Restrisiko siehe SECURITY_RISKS.md. Tests `TestSetupDownloadGetsFreshDirectory`, `TestCheckSetupDirectoryClean`, `TestCleanupRemovesSetupDirectories`.
- **Auto-Update: Austausch der heruntergeladenen Datei vor der Installation (Build 48, 2026-10-16)** – MITTEL (eigenes Review vor dem Build): Zwischen Download (Start) und Installation (Beenden) hätte Schadsoftware mit Benutzerrechten die Datei in `~/.ssh-easy/update/` ersetzen können; das Windows-Setup wird mit Adminrechten gestartet → Rechteausweitung. Fix: `Apply()` prüft die SHA-256 unmittelbar vor der Installation erneut und löscht abweichende Dateien. Das Fable-Review fand danach ein verbleibendes Zeitfenster zwischen Prüfung und `ShellExecute("runas")`: Unter Windows wird das Setup jetzt nur mit Lesefreigabe geöffnet (kein FILE_SHARE_WRITE/DELETE, FILE_FLAG_OPEN_REPARSE_POINT), über diesen Handle gehasht und der Handle erst nach dem Start geschlossen. Der Update-Ordner darf kein Symlink/Reparse-Point sein; ein untergeschobener Symlink am Zielpfad wird entfernt (Anlage mit O_EXCL). Tests `TestApplyRejectsTamperedDownload`, `TestCheckAndDownloadRejectsSymlinkedDownloadDir`, `TestDownloadReplacesPlantedSymlink`.
- **DNS-Fallback leitete unbekannte interne Namen an öffentliche Server weiter (Build 48, 2026-10-16)** – NIEDRIG (Fable-Review): Bei NXDOMAIN des Netz-DNS wurden 1.1.1.1/8.8.8.8 gefragt (Datenschutz, Split-Horizon). Fix: Fallback nur bei Timeout/Serverfehler. Test `TestResolveNotFoundSkipsFallback`.
- **Shift+Einfg-Paste ohne Bracketed Paste (Build 47, 2026-10-15)** – NIEDRIG (Hinweis aus dem Security-Review von Build 44): Der Clipboard-Inhalt ging roh an die Remote-Shell, eine mehrzeilige Zwischenablage (z.B. von einer präparierten Webseite) wurde Zeile für Zeile sofort ausgeführt. Fix: neue Datei `src/bracketed_paste.go`. `bracketedPasteTracker` sitzt hinter dem OSC-52-Filter vor stdout/stderr, reicht alle Bytes unverändert durch und erkennt `ESC[?…2004…h/l` (auch kombiniert und über SSH-Pakete verteilt, Parameterlänge auf 64 Bytes begrenzt). Bei aktivem Modus schließt `preparePaste()` den Text in `ESC[200~ … ESC[201~` ein; `stripPasteMarkers()` entfernt eingebettete Marker wiederholt (verschachtelte Marker wie `ESC[20`+`ESC[201~`+`1~` werden ebenfalls entfernt). 19 neue Tests; Gegenprobe ohne Fix schlägt fehl.
- **OSC-52-Paste-Jacking (Build 45, 2026-10-14)** – MITTEL (automatisches Security-Review von Build 44, security-guidance-Plugin): Ein Server konnte über OSC 52 Steuerzeichen wie `ESC[201~` in die lokale Zwischenablage legen; beim späteren Einfügen in eine lokale Shell hätte das Bracketed Paste beendet und Befehle sofort ausgeführt. Fix: `sanitizeClipboardText()` entfernt alle C0-Steuerzeichen außer Tab/CR/LF, DEL und C1-Zeichen. Teil-Empfehlung „OSC 52 standardmäßig aus“ nicht übernommen – widerspricht dem ausdrücklich angeforderten Zweck (siehe SECURITY_RISKS.md).

- **Security-Audit Build 41 (2026-04-19)** – Sechs Findings behoben:
  - **HOCH: Passwort im Klartext unbegrenzt im RAM** – `ManagedConnection.password` war `string` (immutable) und wurde nie überschrieben. Umgestellt auf `[]byte` + neue `clearPassword()`-Methode; `Disconnect()` nullt das Slice. Reduziert die Lebensdauer sensibler Daten im Speicher deutlich.
  - **HOCH: KeyboardInteractive-Callback mit zusätzlicher String-Kopie** – `pwCopy := password` entfernt, Closure referenziert das Passwort direkt (eine Kopie weniger im Speicher).
  - **MITTEL: Path-Traversal in `expandTilde`** – `~/../../etc/passwd` konnte aus dem Home-Verzeichnis ausbrechen (filepath.Join normalisiert `..`). Neue Guard: wenn das expandierte Ergebnis nicht mehr unter Home liegt, wird der Original-Pfad zurückgegeben.
  - **MITTEL: Symlink-Folge in SSH-Key-Auto-Discovery** – `~/.ssh/id_fake → /etc/shadow` konnte dazu führen dass fremde Dateien als potenzielle Keys geöffnet wurden. Neue `discoverSSHKeys()` prüft `entry.Type().IsRegular()` – Symlinks werden ignoriert.
  - **MITTEL: Blacklist-basierte Key-Erkennung unvollständig** – Blacklist (`known_hosts`, `config`, …) ließ andere Nicht-Key-Dateien durch. Umgestellt auf Whitelist: `looksLikePEMKey()` liest 11 Bytes und akzeptiert nur Dateien mit `-----BEGIN `-Präfix.
  - **MITTEL: Fragiles String-Parsing von Host-Key-Wechsel** – String-Matching gegen "HOST-KEY GEÄNDERT für " ersetzt durch typisierten `*HostKeyChangedError{Hostname}` + `errors.As()`. Robust gegen Nachrichtenänderungen und transparent für Error-Wrapping (`fmt.Errorf("%w", ...)`).
  - **MITTEL: Windows ignoriert 0600 für Log/Config/Keys** – Neue plattform-spezifische `restrictFilePermissions()`: Unix = `chmod 0600`, Windows = `SetNamedSecurityInfo` mit Owner-only DACL + `PROTECTED_DACL_SECURITY_INFORMATION` (blockiert Vererbung). Angewendet auf Log-Datei, Config, Auth-Cache, neue Private-Keys und known_hosts. Keine CGO-Abhängigkeit – verwendet `golang.org/x/sys/windows`.
- **time.Sleep ohne Abbruchmöglichkeit in Reconnect-Goroutine (Build 18, 2026-03-15)** – Ersetzt durch `select { case <-time.After(ReconnectDelay): case <-m.done: return }`. SSHManager hat jetzt eine `Shutdown()`-Methode und ein `done`-Channel für sauberes Programmende ohne Goroutine-Leak.
